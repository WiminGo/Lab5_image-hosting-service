# Архитектура проекта

## Обзор

Проект **Image Hosting Service** — это веб-приложение для организации и хранения изображений в виде альбомов. На этапе каркаса реализована базовая структура с работающей навигацией, mock-данными и полноценным UI. 

## Структура
```text
image-hosting-service/
├── apps/
│ ├── client/ # SPA на React 19 + Vite
│ └── server/ # REST API на Express
├── packages/
│ └── ui/ # Библиотека переиспользуемых React-компонентов
├── architecture.md # Данный документ
├── mvp.md # Функциональные требования к MVP
└── README.md # Описание проекта и инструкции
```

## Компоненты библиотеки `@image-host/ui`

## Взаимодействие проектов

- **`apps/client`** импортирует компоненты из **`@image-host/ui`** через workspace-зависимость (`"@image-host/ui": "*"` в `package.json`).
- **`packages/ui`** объявляет React 19 как `peerDependency`, что гарантирует единую версию React во всём приложении.
- **`apps/server`** в текущей версии является заготовкой для будущего API (health-check endpoint `/api/health`).

## Хранение данных

На этапе каркаса все данные хранятся **в памяти клиента** в файле `apps/client/src/data/mockData.ts`:

- `albums: Album[]` — список альбомов с изображениями
- `getAlbumById(id)` — получение альбома по ID
- `getImagesByAlbumId(albumId)` — получение изображений альбома

Подключение к серверному API и базе данных запланировано в следующих итерациях MVP.

## Тестирование

- **Фреймворк**: Jest + ts-jest
- **Среда**: `jsdom` для клиентских тестов, `node` для серверных
- **Утилиты**: `@testing-library/react` для рендеринга компонентов
- **Требование**: покрытие библиотеки `@image-host/ui` — **не менее 70%** по всем метрикам (statements, branches, functions, lines)

## Конфигурация TypeScript

Во всех проектах включены строгие настройки:
- `strict: true`
- `noImplicitAny: true`
- `noUnusedLocals: true`
- `noUnusedParameters: true`

Использование `any`, `var`, `require` и `module.exports` в исходном коде **запрещено**.
